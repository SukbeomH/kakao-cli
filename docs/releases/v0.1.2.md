# v0.1.2 — 콘솔·CLI·TUI 반응성 개선 (preview)

웹 콘솔의 입력과 영상 대기를 줄이고, 작은 화면의 파일 탐색/조작 영역을 정리했다.
CLI·TUI는 고정 대기·반복 호환성 검사·불필요한 화면 갱신을 줄였다.
v0.1.1의 MSE 장시간 화면 정지 수정도 포함한다.

## 변경 사항

- 웹: 누르는 순간부터 드래그 전달, 세로 휠/트랙패드 전달, 좌우·Shift+휠 제외.
  확정된 한글 입력을 최대 60ms 단위로 묶고 글자 입력 완료 후 Enter를 전달한다.
- 영상: 250ms 프레임 대기 예산, 키프레임 재동기화와 느린 연결 정리,
  H.264 시작 시 불필요한 PNG 캡처 제거, WebCodecs 첫 프레임 즉시 표시 및 후속 출력 병합.
- 품질: 가상 화면 긴 변 기본 1280px, 960/1280/1440/1920 선택과 비례 DPI.
  Compose의 Android 주기는 기본 60Hz로 명시한다. 품질은 연결된 영상 시청자가 공유한다.
- 화면: 파일 탐색을 버튼으로 여는 팝업으로 전환, FPS는 헤더로 이동,
  넓어진 Back/Enter/클립보드 버튼을 하단 우측에 배치.
  앱 전용 가상 화면의 Android 내비게이션 바와 웹 Home 버튼을 제거했다.
- CLI·TUI: 준비 상태에 따른 화면 전환, 이미 선택된 탭 재사용,
  매번 버전/DB 식별 확인을 유지하면서 상세 열 검사만 메모리에서 최대 30초 재사용,
  상세 검사 SQL 일괄 조회, TUI 변경 시 다시 그리기와 50ms 이벤트 tick.
  송신 확인 실패는 uncertain이며 자동 재전송하지 않는다.

## 기존 서버 갱신

Git 배포 저장소에서 webui와 CLI·TUI 코드를 갱신한다. 기존 Android 설정은 유지된다.

```bash
git pull --ff-only
export COMPOSE_DISABLE_ENV_FILE=1
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml build webui
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml up -d --no-deps webui
```

**브라우저를 새로고침해야 클라이언트 변경이 적용된다.** CLI·TUI도 실행 중이면 다시 시작한다.
Git이 없는 배포본은 새 소스를 배포 폴더에 먼저 반영한 뒤 build/up을 실행한다.

### Android 60Hz도 적용하려면

기존 Android가 15Hz이면 webui 갱신만으로는 60Hz가 되지 않는다.
작업을 마친 뒤 아래 순서로 Android 컨테이너도 재생성한다. 잠시 화면 연결이 끊긴다.
기존 `/data` bind와 ADB 상태 볼륨을 유지한다. `down -v`를 사용하지 않는다.

```bash
git pull --ff-only
export COMPOSE_DISABLE_ENV_FILE=1
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml build webui
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml up -d --no-deps redroid
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml run --rm boot
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml up -d --no-deps webui
```

원격 운영 호스트 적용은 사용자가 진행한다.

## Apple Silicon 신규 설치

첨부된 `kakao-cli-0.1.2-macos-arm64.tar.gz`와 `SHA256SUMS.txt`를 같은 폴더에 받는다.

```bash
shasum -a 256 -c SHA256SUMS.txt
tar -xzf kakao-cli-0.1.2-macos-arm64.tar.gz
cd kakao-cli-0.1.2-macos-arm64
brew install lima
bash scripts/setup-macos.sh
```

- 기본 사양: CPU 2개·메모리 4GiB·디스크 20GiB.
- 접속: `http://127.0.0.1:8800` · 종료: `limactl stop kakao`.
- APK·이미지는 설치 시 다운로드하고 검증한다. 인터넷이 필요하다.
- 기존 앱은 자동 재설치/업데이트하지 않는다. 계정 로그인은 직접 진행한다.
- VM 디스크·키·APK·계정 데이터는 첨부 파일에 포함하지 않는다.

## 검증과 한계

로컬 Lima에서 실측한 사례다. 원격 성능 보장이 아니다.

| 측정 | 이전 | 이후 |
|---|---:|---:|
| 설정 화면 스크롤, 같은 928×1728, Android 15→60Hz 전송 평균 | 15.09fps | 46.24fps |
| Android 60Hz, 688×1280 스크롤 전송 평균 | — | 55.73fps |
| 상태 조회 직후 키 HTTP 응답 p95 | 1,843ms | 4.9ms |
| Friends → Chats/All 진입 | 8.15초 | 4.45초 |
| 새 Python CLI 프로세스의 읽기 중앙값 | 214ms | 192ms |
| 상주 DB 읽기 중앙값 | 56.6ms | 44.3ms |
| 가짜 Worker를 쓰는 실제 PTY TUI의 이벤트 표시 p95 | 145ms | 49ms |

정지 화면의 낮은 FPS는 정상이다. 전송 FPS와 브라우저 표시 FPS는 구분해야 하며,
60fps 고정이나 모든 환경의 최소 24fps를 보장하지 않는다.
WebCodecs의 평상시 휠 반응 차이는 작아 확실한 개선으로 해석하지 않았다.
DB 응답 전후 일치를 확인했고, 입력 순서·프레임/포인터 정리·지연 UI·캐시 무효화·TUI 갱신을 회귀 검사했다.
최종 전체 검사 203개와 설치 패키지 추출 후 릴리즈/CLI·TUI 검사 37개가 통과했다.
실제 메시지/파일 송신, 신규 자동 설치 전체 흐름, 재부팅 후 로그인 유지는 미검증이므로 preview를 유지한다.
