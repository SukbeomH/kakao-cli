# v0.1.1 — MSE 화면 정지 수정 (preview)

LAN HTTP에서 Chrome의 자동 렌더러로 웹 콘솔을 사용할 때 약 1분 후 화면이 멈추던 문제를 수정했다.
MSE의 오래된 영상 버퍼를 정리하면서 재생에 필요한 키프레임과 후속 프레임까지 제거되는 문제였다.
키프레임의 실제 미디어 시간을 전달하고, 안전한 키프레임을 보존하며 버퍼를 정리한다.

## 기존 원격 서버 갱신

실제 Git 배포 저장소에서 실행한다.

```bash
git pull --ff-only
export COMPOSE_DISABLE_ENV_FILE=1
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml build webui
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml up -d --no-deps webui
```

**적용 후 브라우저를 새로고침해야 한다.** redroid 재시작이나 카카오톡 재로그인은 필요하지 않다.
Git 저장소가 아닌 archive 배포본이면 최신 소스를 배포 경로에 먼저 동기화한 뒤 build/up만 실행한다.

## Apple Silicon 신규 설치

첨부된 `kakao-cli-0.1.1-macos-arm64.tar.gz`와 `SHA256SUMS.txt`를 같은 폴더에 받는다.

```bash
shasum -a 256 -c SHA256SUMS.txt
tar -xzf kakao-cli-0.1.1-macos-arm64.tar.gz
cd kakao-cli-0.1.1-macos-arm64
brew install lima
bash scripts/setup-macos.sh
```

- 기본 사양: CPU 2개·메모리 4GiB·디스크 20GiB.
- 접속: http://127.0.0.1:8800 · 종료: `limactl stop kakao`.
- APK·이미지는 설치 시 다운로드하고 검증한다. 인터넷이 필요하다.
- 이미 설치된 앱은 재설치·업데이트하지 않는다. 계정 로그인은 직접 진행한다.
- VM 디스크·ADB 키·계정 데이터는 릴리즈에 포함하지 않는다.

## 검증 범위

- 수정 당시 전체 테스트 171개 통과.
- 버퍼 정리 회귀 테스트는 수정 전 코드에서 실패하고 수정 후 통과.
- 실제 브라우저의 MSE 재생 시간 125초, 두 차례 버퍼 정리 후에도 재생 유지 확인.
- 원격 운영 서버 적용은 사용자가 진행한다.
- Mac 자동 설치 전체 흐름은 모의 테스트로 확인했다. 계정 로그인·DB 수신·송수신·재부팅 후 로그인 유지는 미검증이므로 preview를 유지한다.
