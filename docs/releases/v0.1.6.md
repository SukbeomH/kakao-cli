# v0.1.6 — VM VPN 대화 조회·전송 멈춤 수정 (preview)

`kakao-cli 0.1.6` 배포입니다. 공통 Python 모듈은 변경이 없어 `android-console 0.1.2`를 유지합니다.
v0.1.5에서 Tailscale Exit node를 선택하고 외부 IP도 정상이어도, Android의 카카오 TLS 통신이
멈춰 채팅방 대화가 비어 보이고 전송되지 않던 문제를 수정했습니다.

## 원인과 수정

Android/Docker의 MTU 1500과 Tailscale의 MTU 1280 사이에서 일부 카카오 서버의 TCP/TLS 통신이
정지했습니다. 짧은 외부 IP 응답과 TCP 연결 확인만으로 발견되지 않던 문제입니다.

- VM의 `tailscale0`를 지나는 양방향 전달 TCP의 SYN/SYN-ACK에 MSS 보정을 적용합니다.
  고정 크기 대신 경로 MTU를 사용하며, 기존 방화벽 규칙을 초기화하지 않습니다.
- 반복 실행 시 같은 규칙을 중복 추가하지 않고 Docker·tailscaled와 xtables 잠금을 공유합니다.
- `kakao-vpn-mss.service`와 `xt_TCPMSS` 부팅 모듈 설정을 추가했습니다.
  VPN 관리 에이전트보다 먼저 적용하고 tailscaled 재시작 때도 규칙을 다시 확인합니다.
- macOS 네트워크, Android 앱 데이터·로그인 정보는 변경하지 않습니다.

## 기존 VM에 반드시 적용할 단계

**webui 이미지 재빌드나 Python wheel 교체만으로는 MSS 보정이 적용되지 않습니다.**
VM 호스트 설정을 준비하는 아래 스크립트를 새 버전에서 다시 실행해야 합니다.
VM이 중지돼 있다면 먼저 `limactl start kakao`로 실행하세요.

```sh
git pull --ff-only
./scripts/setup-vm-vpn.sh kakao
kakao vpn status --json
limactl shell --workdir / kakao sudo systemctl is-active kakao-vpn-mss kakao-network-agent
```

기존 v0.1.5의 Tailscale 패키지·인증·선택한 Exit node를 유지합니다.
처음 설치하는 경우에는 [VM VPN 가이드](../vm-vpn.md)에 따라 VM 내부 Tailscale 패키지를 먼저 준비합니다.

적용 전에 만들어진 TCP 연결은 새 MSS 값을 사용하지 않으므로, 대화 조회가 계속 멈춰 있으면
카카오톡 앱을 종료 후 다시 실행합니다. **앱 데이터 삭제·재설치·재로그인은 필요하지 않습니다.**
Exit node 변경 후에도 기존 연결이 남아 있으면 앱 재실행이 필요할 수 있습니다.
이번 확인에서는 VM의 기존 ADB root 상태도 복구했습니다. 이는 CLI DB 읽기에 필요하며,
MSS 보정 서비스 자체가 ADB 권한을 변경하지는 않습니다.

## 검증

- 전체 자동 테스트 272개. 신규 검사는 규칙의 방향·범위·반복 실행과 서비스 시작 순서를 확인합니다.
- 실제 VM에서 Android 네트워크 공간의 카카오 HTTPS 요청이 7~12초 타임아웃에서 약 0.6초 정상 응답으로 개선됐습니다.
- 카카오톡 앱 재실행 후 기존 채팅방의 대화 표시를 확인했고, 사용자가 직접 재시도해 **정상 전송을 확인**했습니다.
  에이전트는 테스트 메시지를 보내지 않았습니다.
- tailscaled 재시작 후 MSS 규칙과 관리 서비스가 복구되고 HTTPS 응답이 정상인 것을 확인했습니다.
  전체 VM 재부팅은 이번 수정 검증에 포함하지 않았습니다.
- macOS의 IPv4/IPv6 기본 경로와 DNS는 작업 전과 동일합니다.

이는 모든 네트워크·앱·Exit node의 성공을 보장하거나 신규 KakaoTalk 설치 전체를 검증하는 배포는 아닙니다.
기존과 같이 preview를 유지합니다.
