# v0.1.4 — 클립보드·우클릭·키보드·한글 입력 개선 (preview)

`kakao-cli 0.1.4`와 공통 `android-console 0.1.1` 배포다. 기존 Kakao 웹 콘솔과 독립
Android 콘솔이 같은 입력·영상·클립보드 구현을 사용한다.

## 변경 사항

- **양방향 클립보드**: 하단 **📋 가져오기**로 기기 텍스트를 로컬로 복사하고,
  **📋 넣기**로 로컬 텍스트를 기기 클립보드에 저장한다. 넣기 버튼은 현재 입력 칸에
  자동으로 붙여넣지 않는다. 화면에 포커스한 Ctrl/Cmd+V는 바로 붙여넣는다.
- **HTTP·권한 거부 대응**: 브라우저 클립보드 접근이 불가능하면 직접 복사·붙여넣는 창을
  제공한다. 새 기기 읽기의 응답이 없으면 캐시를 성공으로 반환하지 않는다.
- **우클릭**: H.264 화면에서 Android 마우스 보조 버튼의 누름·해제를 전달한다.
  PNG에서는 지원 안내를 표시하고 파일 탐색 창의 브라우저 메뉴는 유지한다.
- **키보드 반응성**: 확정 글자의 60ms 대기를 없앴다. 요청은 하나씩 완료를 확인하고,
  대기 중인 연속 글자만 합친다. Enter·붙여넣기 순서를 보장하고 불확실한 입력을 재전송하지 않는다.
  PNG 캡처도 입력 처리와 분리했다.
- **한글 실시간 조합**: 다음 글자를 칠 때까지 마지막 음절이 보이지 않던 문제를 수정했다.
  `ㅎ → 하 → 한`을 Android의 같은 조합 영역에서 갱신하고 한 번만 확정한다.
  조합 중 Enter는 확정만 하며, 입력 칸을 바꾼 뒤 도착한 이전 요청을 거부한다.
- **입력 보조 앱**: 자체 MIT 앱 Android Console Input의 소스·APK·해시를 공통 패키지에 포함한다.
  기존 ADBKeyBoard 사용 기기의 첫 조합 때 설치·등록·선택을 확인한다. 사용자가 선택한 다른
  입력기는 자동으로 바꾸지 않는다. 기존 CLI/TUI의 Unicode 입력도 지원한다.
- **Mac 기동·패키징**: Kakao 포트 8800도 고정 전달한다(Lima 2.2 이상).
  런타임 내보내기의 Python 캐시 제외와 공통 패키지 버전 일치를 보강했다.

제3자 APK와 이미지는 설치 시 검증해 다운로드한다. 자체 MIT 입력 보조 앱만 소스·해시와 함께 포함한다.
자세한 신규 설치 방법은 [설치 가이드](../release.md)를 따른다.

## 기존 서버 갱신

Linux/원격 운영 호스트:

```sh
git pull --ff-only
export COMPOSE_DISABLE_ENV_FILE=1
docker compose -f deploy/compose.yaml -f deploy/compose.live.yaml up -d --no-deps --build webui
```

Mac Kakao VM:

```sh
git pull --ff-only
limactl start kakao
./scripts/lima-compose.sh up -d --no-deps --build webui
```

웹 콘솔 갱신 뒤 브라우저를 새로고침한다. 기존 Android 컨테이너와 데이터를 유지한다.
기존 Lima VM에서 8800 연결이 안 되면 VM을 종료하고 `limactl edit kakao`의 해당
`portForwards` 항목에 `static: true`를 추가한 뒤 다시 시작한다. 저장소 템플릿 변경은 기존 VM에
자동 반영되지 않는다. `down -v`로 볼륨을 지우지 않는다.

독립 콘솔은 새 번들을 별도 폴더에 풀고 기존 VM 이름과 데이터 디렉터리를 유지한 채
`./lima-compose.sh up -d --no-deps --build webui`로 갱신한다.
Python만 설치하면 두 wheel을 함께 지정한다:

```sh
python3 -m pip install ./android_console-0.1.1-py3-none-any.whl ./kakao_cli-0.1.4-py3-none-any.whl
```

## 검증 범위

전체 pytest **243개 통과**(76.33초), 두 프로필의 브라우저 회귀 검사를 확인했다.
깨끗한 환경에서 두 wheel 설치·CLI 버전·보조 APK 해시·공통 UI를 검사했고,
설치된 wheel에서 내보낸 독립 런타임도 별도 환경에 설치해 버전 일치를 확인했다.
APK의 서명·SHA-256과 현재 Java 소스에서 컴파일한 DEX의 일치도 확인했다.
실제 독립 VM에서 양방향 macOS/Android 클립보드, Android 우클릭 메뉴,
미러·가상 화면의 한글 조합·수정·취소·확정 및 입력 세션 보호를 확인했다.
macOS 입력기별 물리 키 검사는 이번 범위에 포함하지 않았다.

이전 실측에서 한글 입력 처리 응답 중앙값은 WebCodecs **88→28ms**, PNG **86→26ms**였다.
화면 표시까지의 지연이나 모든 호스트의 성능 보장이 아닌 해당 조건의 처리 응답 측정이다.
정지 화면을 포함해 최소 24fps/고정 60fps를 보장하지 않는다. KakaoTalk 신규 자동 설치 전체와
실제 메시지 송신·로그인 유지의 검증 범위를 확대하는 배포가 아니므로 preview를 유지한다.
