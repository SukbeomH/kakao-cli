## 1. JungHoonGhae/openkakao-cli (Rust, macOS)

### 1.1 기본 정보
- 언어/런타임: Rust edition 2021, toolchain 1.95.0 (`rust-toolchain.toml`, `Cargo.toml:1-7`). 바이너리 이름 `openkakao-cli`. 버전 1.9.0.
- 핵심 의존성(`Cargo.toml:17-55`, 관찰): `tokio`+`tokio-rustls`/`rustls`(TLS), `reqwest`(blocking, rustls-tls)(REST), `rusqlite` **bundled-sqlcipher**(로컬 암호화 DB), `rsa`(sha1 feature), `aes-gcm`, `hmac`, `sha1`/`sha2`, `bson`, `byteorder`(LOCO 패킷), `plist`(preferences 파싱), `clap`(CLI), `zeroize`. macOS 전용 타깃 의존성: `accessibility`, `accessibility-sys`, `core-foundation`, `core-graphics`(`Cargo.toml:57-62`). 비-macOS에서는 AX 코드가 cfg 스텁으로 컴파일만 되고 동작 안 함.
- 라이선스 MIT. 최종 커밋 2026-10-11 (`6ca6ea2`). Stars 133 / forks 41 / open issues 4 (gh api).
- 설치: Homebrew tap `JungHoonGhae/openkakao` 또는 `cargo install --path .`. macOS + KakaoTalk 설치·로그인 필요.

### 1.2 통합 방식 — 4가지를 모두 구현한 하이브리드
openkakao-cli는 세 가지 접근을 동시에 가진 유일한 프로젝트다. 저자 스스로 LOCO/REST 서버 경로는 "최신 빌드에서 대부분 깨짐"이라고 README에 명시하고, **로그인 없는 AX 경로를 권장**한다(`README.en.md` NOTE 블록).

(a) **LOCO 프로토콜 재구현** (`src/loco/`) — 관찰:
- 패킷 헤더 22바이트 고정(`src/loco/packet.rs:8`, `HEADER_SIZE=22`): LE u32 packetId(4) + LE i16 status(2) + 11바이트 ASCII null-padded method + u8 bodyType(1) + LE u32 bodyLength(4). 바디는 BSON(`bson::to_vec`/`from_slice`, `packet.rs:23,84`).
- 핸드셰이크(`src/loco/crypto.rs:51-66`): 클라이언트가 AES-128 키를 난수 생성 → KakaoTalk의 2048비트 RSA 공개키(e=3)로 RSA-OAEP(SHA-1) 암호화 → `[keySize=256 LE][keyEncType=16 LE][encType=3 LE][encryptedKey]` 전송. RSA 공개키 DER은 바이너리에서 추출한 하드코딩 상수(존재만 기록, `crypto.rs:13-20`).
- 레코드 암호화(`crypto.rs:25,70-106`): AES-128-**GCM** (encType=3; 주석상 과거 2=CFB에서 전환). 와이어 프레임 `[size:4 LE][nonce:12][ciphertext+tag:N+16]`.
- 접속 흐름(`src/loco/client.rs:616-668`, `full_connect`): ① Booking `GETCONF` → `booking-loco.kakao.com:443` TLS(`client.rs:30-31,368-379`), ② Checkin `CHECKIN` → booking 응답의 `ticket.lsl` 호스트, 포트는 `wifi.ports`; TLS 443 우선, 레거시 포트, 995 폴백 순차 시도(`client.rs:382-430`), ③ 할당된 LOCO 서버에 연결 후 `LOGINLIST` 로그인(`client.rs:589-612`).
- 요청 바디(관찰, `client.rs:34-95`): `GETCONF`={MCCMNC:"99999", os:"mac", model:"", userId}; `CHECKIN`={userId, os:"mac", ntype:0, appVer, MCCMNC, lang:"ko", countryISO:"KR", useSub:true}; `LOGINLIST`={appVer, prtVer:"1", os:"mac", lang, duuid, oauthToken, dtype:2, ntype:0, MCCMNC, revision:0, chatIds[], maxIds[], lastTokenId:0, lbk:0, rp:Binary(00 00 FF FF 00 00), bg:false}.
- 명령어(관찰): GETCONF/CHECKIN/LOGINLIST(접속), CHATONROOM(방 입장, `send.rs:109`), WRITE(텍스트 전송, `send.rs:148`), SHIP(미디어, `send.rs:290`), DELETEMSG/REWRITE/ACTION/NOTIREAD(`send.rs`), SYNCMSG(메시지 동기화, `analytics.rs:81`), POST(업로드, `client.rs:790`), PING(60초 keepalive, `watch.rs:1142`), MSG/CHANGESVR(서버 푸시 처리, `watch.rs:1153,1173`), BLSYNC/GETMEM 등.
- TLS 검증(`client.rs:312-331`): 커스텀 verifier로 `kakao.com`/`probe.kakao.com` 이름만 수용. **IP 주소로 리다이렉트되는 checkin 서버에서 인증서 이름 불일치로 깨지는 문제 존재**(issue #61 open, 인증서가 `DnsName("kakao.com")`만 유효한데 서버가 IP:5228로 옴).

(b) **REST** (`src/rest.rs`) — 관찰:
- 호스트: `katalk.kakao.com`(`rest.rs:18`), `talk-pilsner.kakao.com`(`rest.rs:19`). 경로는 전부 `/mac/...json`(profile3/me, account/more_settings, friends/update, profile/list, alarm_keywords/list, account/renew_token, account/oauth2_token 등, `rest.rs:39-493`).
- 헤더: `A: mac/{appVer}/ko`, `User-Agent: KT/{appVer} Mc/26.1.0 ko`, `Authorization`(oauth) 또는 pilsner용 `rest_token`, 미인증 요청엔 `X-VC`(`rest.rs:302-420`).
- **X-VC 계산(`rest.rs:498-504`)**: `SHA-512("YLLAS|{loginId}|{uuid}|GRAEB|{userAgent}")`의 앞 16 hex 문자. 고정 접두/접미 문자열 2개는 상수로 존재(존재만 기록).
- 기기 등록 경로(`rest.rs:442-477`): `passcodeLogin/generate`, `passcodeLogin/registerDevice`. **단, 최신 macOS 빌드는 이 엔드포인트를 더 이상 제공하지 않아 404**(issue #22).

(c) **로컬 SQLCipher DB 읽기** (`src/local_db.rs`) — 관찰 + 추론:
- DB 위치: `~/Library/Containers/com.kakao.KakaoTalkMac/Data/Library/Application Support/com.kakao.KakaoTalkMac/<파생된 hex 이름>`(`local_db.rs:388-391`).
- userId 획득(`local_db.rs:65-172`): Containers Preferences의 `com.kakao.KakaoTalkMac.*.plist`에서 추출. 못 찾으면 plist의 SHA-512(userId) revision 마커로부터 **바운드 브루트포스**(`recover_user_id_from_sha512`, `local_db.rs:210-263`). 기기 UUID는 `ioreg`의 `IOPlatformUUID`(`local_db.rs:41-62`).
- (구) 키 유도(`local_db.rs:291-351`): DB 파일명과 SQLCipher 키 모두 userId+UUID 조합 템플릿 문자열 → PBKDF2-HMAC-SHA256(iter 100,000, keylen 128) → hex/substring. salt는 UUID의 해시/슬라이스. `cipher_compatibility=3` 후 `PRAGMA key`로 연다(`local_db.rs:463-465`).
- **그러나 KakaoTalk 26.5.0+에서 이 경로가 깨짐**(`docs/research/db-key-derivation.md`, issue #39/#40/#43). 정적 분석 결과: 구 템플릿 문자열(`..F.`, `..|` 마커)이 바이너리에서 사라지고 새 템플릿(`J|%lld|O|%@|SH`, `KY|%lld|%@`, 소스 `/MacTalk/NT/NTDataStore.m`)으로 바뀌었으며, 구 DB를 새 이름+키로 마이그레이션한다. 추가 조사에서 secureKey/databaseName이 **파생값이 아니라 NTSetting에 AES로 저장된 값**이라는 증거가 나옴 → 오프라인 브루트포스 실패. 동적 훅(`sqlite3_key`)으로 raw 키 캡처는 준비됐으나, 앱 사본 재서명 시 keychain 상실로 로그아웃되어 DB를 안 열어 **NO-GO**로 종결(issue #43). 결론: **현재 로컬 DB 직접 복호화 경로는 사실상 봉인됨**.

(d) **AX(Accessibility) 자동화** (`src/ax_send.rs`, 2267줄) — 관찰, 현재 **권장 경로**:
- 번들 ID `com.kakao.KakaoTalkMac` 확인, `AXIsProcessTrusted`로 권한 체크(`ax_send.rs:312-332`).
- 전송: 채팅 리스트에서 정확히 일치하는 행 선택 → 메시지 입력창(`AXScrollArea`>`AXTextArea`) 찾기 → 값 설정 → Return. 채팅 행에 `AXPress`가 없는 최신 빌드를 위해 시스템 hit-test + 더블클릭 폴백(`ax_send.rs:1165-1322`, CHANGELOG 1.8.3). 이벤트는 `CGEventPostToPid`로 대상 pid에 직접 전달(포그라운드 탈취 레이스 회피, Peekaboo에서 차용; README Acknowledgments).
- 읽기(`ax-read`): 열린 채팅창의 메시지 버블(`AXTextArea` 유무로 텍스트/비텍스트 구분)을 스크랩(`ax_send.rs:1632+`).
- 한계: 메인 창이 최소화/다른 Space면 창을 못 찾아 실패(자동 복원은 포그라운드 탈취 위험으로 안 함).

### 1.3 수신 감지 — notif-watch (설계적으로 가장 주목할 만함)
`src/commands/notif_watch.rs`(1080줄, 관찰): macOS 알림센터 DB `~/Library/Group Containers/group.com.apple.usernoted/db2/db`(평문 SQLite, WAL)를 read-only 폴링(`notif_watch.rs:341-366`). `app.identifier = com.kakao.KakaoTalkMac`인 record의 payload를 파싱. payload(issue #42 라이브 검증): `/req/body`=메시지 본문, `/req/titl`=방/발신자, `/req/iden`=`방ID_메시지ID`(dedup 키), `/date`=CFAbsoluteTime, `/req/atta[].pat`=이미지 첨부 경로.
- 장점(관찰): 창 상태 무관(최소화/다른 Space OK), 자기 발신 자동 배제(알림은 수신에만), 서버/로그인/복호화 불필요 → **밴 표면 0**.
- 한계: 음소거/알림 off 채팅과 현재 포커스된 채팅은 알림이 안 떠서 안 보임. 알림센터에서 이미 지워진 메시지는 replay 불가.
- `--durable`(CHANGELOG 1.8.0): `~/.config/openkakao/receive_inbox.db`에 persist, 워커 lease, 지수 백오프 재시도, 8회 실패 시 격리. **at-least-once** 전달(chat_id+log_id를 idempotency 키로). launchd LaunchAgent 예제 제공.
- `ax-watch`: 채팅 리스트 unread 증가 폴링(창 열려 있어야 함). notif-watch의 보완재.

### 1.4 인증·자격 저장
- 자격은 `~/.config/openkakao/credentials.json`에 저장, **파일 권한 0600 강제**(`src/credentials.rs:9-81`). Keychain 미사용. 구조체 `KakaoCredentials`={oauth_token, user_id, device_uuid, device_name, app_version, user_agent, a_header, refresh_token, email, rest_token}(`src/model.rs:6-23`).
- 설정은 `~/.config/openkakao/config.toml`(`src/config.rs:94-96`). `[safety] allow_loco_write`, `allow_ax_send`, `allowed_send_chats`.
- 과거 토큰 추출(관찰, `src/auth.rs`): KakaoTalk `NSURLCache`의 `Cache.db`(`~/Library/Containers/.../Caches/Cache.db`)를 임시 복사 후 `cfurl_cache_*` 테이블에서 Authorization/X-VC 헤더가 든 응답 추출. **최신 빌드는 인증 응답을 캐시에 안 써서 이 경로가 비어 깨짐**(`docs/research/credential-storage.md`, issue #15/#22).
- 토큰이 실제로 사는 곳(연구 노트): Preferences plist의 난독 키 2개에 든 96바이트 AES 암호문 + Application Support의 자가암호 파일. CommonCrypto + `IOPlatformUUID` 기반 PBKDF2 키. Secure Enclave/Keychain 미사용이라 원리상 복호화 가능하나 아직 미구현.
- `login --manual`: 이메일/비밀번호. device_uuid는 `IOPlatformUUID`의 SHA1(20)+SHA256(32)=52바이트를 base64(`src/commands/auth.rs:320-331`). 미등록 기기는 status=-100 → 과거엔 passcode 등록 자동화 시도했으나 엔드포인트 404로 되돌림. **미등록 기기 반복 로그인 시 서브디바이스 로그인 차단 실제 사례**(#20, #22).

### 1.5 CLI 표면·아키텍처·테스트
- 전역 플래그(`src/main.rs:39-76`): `--json`, `--no-color`, `--unattended`, `--allow-non-interactive-send`, `--allow-watch-side-effects`, `--no-prefix`(기본은 발신 메시지에 `🤖 [Sent via openkakao]` 접두), `--completion-promise`.
- 서브커맨드(`src/main.rs:79-645`, 60+개): 읽기(chats/read/members/me/friends/profile/search/export/stats/unread), LOCO 쓰기(send/send-me/send-photo/send-file/delete/mark-read/react/edit/download), 로컬(local-chats/local-read/local-search/local-schema), AX(ax-read/ax-watch/local-send/local-send-photo), 수신(watch/notif-watch), safe-send(propose/list/approve/cancel), 진단(doctor/probe/profile-hints), auth(login/renew/relogin). `--rest` 플래그로 일부 명령을 REST 경로로.
- **safe-send(에이전트용 안전 설계, 주목)**: propose는 로컬 outbox(`~/.config/openkakao/safe_send_outbox.db`, 0600)에만 기록하고 절대 전송 안 함. approve는 대화형 터미널 + 12자 승인 코드 + macOS 기기소유자 인증(Touch ID/암호, `native/macos_user_presence.m`의 LAContext `LAPolicyDeviceOwnerAuthentication`) 둘 다 요구, unattended 우회 없음. 15분 만료. 레이트리밋(채팅당 3/시, 전역 10/시·20/일, 클레임 간 최소 10초). 전송 결과를 verified/not_sent/uncertain으로 분류, uncertain은 자동 재시도 안 함.
- 테스트(`tests/`, 11개 파일): loco_packet/crypto/message/client, message_db, auth_flow, safe_send_outbox, receive_inbox, local_db_user_id, cli, launchd_notif_watch. 프로토콜 빌더/암호화 단위 테스트 충실.
- 연구 노트(`docs/research/`): android-apk-26.7.1(LOCO 정적 분석, 패킷 프레이밍 불변 확인), credential-storage, db-key-derivation, message-envelopes-26.7, local-receive-strategy. **방법론: 서명 아티팩트 해시 기록, 정적 전용, 계정 위험 0 원칙 명시.** Android 관찰을 Mac에 그대로 이식하지 않는 보수적 규칙이 돋보인다.

### 1.6 한계·위험·유지보수
- 서버 로그인(login/LOCO) 최신 빌드에서 대부분 깨짐. 로컬 DB도 26.5.0+에서 봉인. checkin 인증서 문제(#61 open).
- **계정 위험**: 저자가 테스트 중 2계정 중 1개 삭제(LOCO write 수행 계정, #13). v1.1.0부터 LOCO write 기본 비활성. 미등록 기기 반복 로그인 차단 사례.
- 유지보수: 활발(2026-10-11 커밋, 외부 기여자 다수). 방향을 AX/notif 로그인리스 경로로 명확히 전환 중(ROADMAP).

### 1.7 채택할 아이디어 / 피할 함정
- 채택: ① **notif-watch(알림센터 DB) 수신 감지** — 로그인리스·창무관·자기발신배제·밴표면0. ② **safe-send 제안/승인 분리 + OS 기기소유자 인증 + 레이트리밋** — 에이전트 안전 설계의 모범. ③ 전송 결과 verified/not_sent/uncertain 3분류로 blind 재시도 방지. ④ `--json`/NDJSON 일급 지원, 자격 0600, zeroize. ⑤ 정적 전용·해시 기록·보수적 이식 연구 방법론.
- 함정: ① LOCO 서버 경로는 유지보수 부담 크고 밴 위험·잦은 파손. ② 로컬 DB 키는 벤더가 마이그레이션/AES 저장으로 적극 봉인 → 지속 가능성 낮음. ③ AX는 창 상태·Space·앱 UI 변경에 취약(빌드마다 AXPress 유무 등 땜질 반복). ④ 미등록 기기 로그인 반복은 계정 차단 트리거.

## 2. silver-flight-group/kakaocli (Swift, macOS)

### 2.1 기본 정보
- 언어/런타임: Swift tools 6.0, macOS 14+ (`Package.swift:1,7`). CLI 버전 문자열 0.4.1(`KakaoCLI.swift:8`)이나 CHANGELOG/SKILL은 0.5.0, 이슈는 Homebrew 0.6.0 — **버전 표기 불일치**. 라이선스 MIT(2026 Silver Flight Group). 최종 커밋 2026-03-30. Stars 164 / forks 70 / open issues 22.
- 의존성(관찰): 외부 SPM은 `swift-argument-parser` 1.7.0 단 하나(`Package.resolved:9-13`). 시스템 라이브러리 `CSQLCipher`(pkgConfig sqlcipher, Homebrew 제공, `Package.swift:27-31`). Apple 프레임워크: CommonCrypto, AppKit/ApplicationServices, Vision(OCR), Foundation/URLSession. 타깃: executable `KakaoCLI`, lib `KakaoCore`, test `KakaoCoreTests`.
- **미선언 런타임 의존**: harvest `--scroll`이 외부 CLI `peekaboo`/`cliclick`를 shell out(`ChatHarvester.swift:327-391`). Package.swift/README/SKILL에 없음 → 미설치 시 무음 실패(추론).

### 2.2 통합 방식 — 로컬 SQLCipher DB 읽기 + AX 자동화 (서버 접촉 0)
README가 명시적으로 "프로토콜 리버싱·Kakao API 호출 안 함"(`README.md:12-13`). grep 결과 LOCO/5223/booking/REST 코드 전무 — **유일한 네트워크 송신은 사용자 설정 webhook뿐**(관찰). 메시지/키 데이터는 그 webhook 외에는 기기를 떠나지 않음.

**로컬 DB 읽기**(`DatabaseReader.swift`, 관찰):
- DB 위치: openkakao-cli와 동일한 Containers Application Support 경로. 파일명은 78자 소문자 hex(`.db` optional), 정규식 스캔으로 발견(`DeviceInfo.swift:130-148`) 또는 직접 유도.
- SQLCipher: `sqlite3_open_v2`(READONLY|NOMUTEX). **cipher compatibility [3,4] 순차 시도**(`:26`) — `PRAGMA cipher_default_compatibility=n` → `PRAGMA KEY='<key>'` → `SELECT count(*) FROM sqlite_master` 프로브로 키 검증(`:41-43`). 모드 3=레거시, 4=신규. **키가 PRAGMA SQL 문자열에 직접 보간**됨(`:42`) — hex라 실질 위험 낮으나 injection-shaped.
- 키 유도(`KeyDerivation.swift`, 관찰; 상수 원문 미기재): PBKDF2-HMAC-SHA256, iter 100,000, 128바이트 출력(`:10-31`). `hashedDeviceUUID=base64(SHA1(uuid)||SHA256(uuid))`(`:34-51`). `databaseName`=userId+역순 UUID를 고정 토큰 배열로 조합(고정 구분자 상수 `:55-56`), salt=역순 hashedUUID, PBKDF2, hex, slice`[28..106]`→78 hex=파일명(테스트 `KeyDerivationTests.swift:16`). `secureKey`=또 다른 고정 토큰 배열(`:71-72`)을 "F"로 join 후 역순, salt=UUID[floor(len*0.3)..], PBKDF2 hex=SQLCipher 키. 입력은 정수 userId + IOPlatformUUID.
  - 주: openkakao-cli와 **같은 공개 gist 유래 공식**이며(동일 iter/길이/substring), 둘 다 최신 빌드 봉인 문제를 공유한다.
- 기기 UUID: `ioreg -rd1 -c IOPlatformExpertDevice` 정규식(`DeviceInfo.swift:8-24`), `auth --uuid` 오버라이드.
- **userId 발견(4단계, 관찰 `DeviceInfo.swift:59-127`)**: ① `FSChatWindowTransparency<id>` plist 키 공통 접미, ② 직접 키(userId/user_id/KAKAO_USER_ID), ③ **SHA-512 역브루트포스** — 신규 빌드가 `DESIGNATEDFRIENDSREVISION:<sha512hex>` 키에 SHA-512(userId)를 저장, `0..1e9` 순회하며 `CC_SHA512(String(i))` 비교, **10초 타임아웃**(`:198-225`), ④ `FSChatWindowFrame_<id>` 공통 접미. 폴백: `AlertKakaoIDsList` 후보를 DB 키로 trial-and-error. `--user-id` 수동 오버라이드.
- 스키마(관찰): `NTChatRoom`(chatId,type,chatName,lastLogId,countOfNewMessage,directChatMemberUserId,displayMemberIds), `NTUser`(userId,displayName,nickName; join linkId=0), `NTChatMessage`(logId,chatId,authorId,message,type,sentAt), `NTChatContext.userId`(내 userId). 타임스탬프=초단위 epoch. 채팅 타입 매핑은 잠정(0→direct,1→group,else unknown, `:361-370`).

**전송 = UI 자동화**(`KakaoAutomator.swift:12-117`, 관찰): AppleScript는 로그인 상태 감지·창 띄우기(lifecycle)에만 사용(`AppLifecycle.swift:107-308`), 전송엔 미사용. 흐름: 앱 활성화 → AX id로 `Main Window` 찾기 → 비메인(채팅) 창 전부 닫기(오타겟 방지) → Chats 탭(AXCheckBox id `chatrooms`) → 채팅 행 매칭(`AXStaticText` id `_NS:18`), 자기채팅은 "badge me" AXImage로 식별 → `kAXSelectedRowsAttribute` 선택 + Enter(keyCode 36), 폴백 CGEvent 더블클릭 → 입력창(`AXScrollArea` 중 `AXTable` 없는 것의 `AXTextArea`)에 `AXUIElementSetAttributeValue`로 값 설정(폴백 유니코드 CGEvent 키입력) → Return → 창 닫기. **클립보드 미사용**(NSPasteboard 전무).
- LoginAutomator(`LoginAutomator.swift`): 로그인 창 AXTextField=이메일, AXSecureTextField(또는 2번째 AXTextField)=비밀번호, "로그인 유지" 자동 체크, 로그인 버튼/Return, 상태바 메뉴 30초 폴링, OTP/2FA/오답/네트워크 오류를 AXStaticText 한/영 부분문자열로 분류. 실패 시 AX 트리를 stderr로 덤프(UI 텍스트 유출 가능).
- CredentialStore(`CredentialStore.swift`): macOS **Keychain을 `/usr/bin/security` CLI로** 사용(Security.framework 아님 — `swift run` 하 코드서명 ACL 회피, `:65-67`). service `com.kakaocli.credentials`. **보안 주의(AGENTS.md:29-33)**: 항목에 per-app ACL이 없어 같은 사용자의 아무 프로세스나 비밀번호를 읽을 수 있음. `login --password`는 argv/history 노출.

### 2.3 Sync / Watch / Harvest
- **DatabaseWatcher = 폴링(FSEvents 아님)**(`DatabaseWatcher.swift:24-51`): `while running { fetch; sleep(2.0s) }`. high-water `lastLogId`, **매 폴링마다 DB 재오픈/클로즈**(WAL 커밋 반영, `:66-72`), `logId>lastLogId ORDER BY logId ASC LIMIT 100`. 한계: 로컬 DB 캐시가 **채팅당 ~1–4개 메시지만** 보유(CLAUDE.md:69) → fast burst 유실 가능.
- WebhookPublisher payload(관찰): JSON `type,log_id,chat_id,chat_name,sender_id,sender,text,message_type,timestamp(ISO8601),is_from_me`. stdout은 NDJSON, webhook은 배치 배열 POST(`User-Agent: kakaocli/0.3.0`, 10s, 세마포어 동기). **서명/HMAC 없음, http 허용** → 평문 메시지 유출 위험.
- HarvestCommand/ChatHarvester(관찰): UI 구동으로 (a) DB에 없는 표시명 수집(그룹은 `(unknown)`), (b) `--scroll`로 "이전 대화 보기" 반복 클릭해 서버 히스토리를 로컬 DB로 당겨옴, (c) "톡드라이브" 유료 팝업 자동 닫기, (d) `~/.kakaocli/metadata.json` 저장. unread>0 채팅은 읽음 방지로 skip. 이름 매핑이 **위치 기반 UI행[i]↔DB행[i]**라 불안정(CLAUDE.md:60 스스로 명시). OCR은 Vision(en+ko), 스크린샷을 `/tmp`에 기록.

### 2.4 CLI 표면·설정·테스트
- 서브커맨드(`KakaoCLI.swift:9-22`): auth, chats, harvest, inspect, login, messages, query, schema, search, send, status, sync. 모든 읽기 명령이 `--db`/`--key` 오버라이드 수용. `--json`은 JSONSerialization dict(nil 시 키셋 가변). `query`는 **임의 read-only SQL** 실행(JSON array-of-arrays). `sync --follow/--webhook/--interval/--since-log-id`.
- 상태 파일: `~/.kakaocli/metadata.json`뿐(`MetadataStore.swift:18-22`). 자격은 Keychain. **단, MetadataStore는 harvest가 쓰기만 하고 읽기 명령에서 안 읽음** → harvest한 이름이 실제 `chats` 출력에 반영 안 됨(추론).
- 테스트: KeyDerivation 결정성/길이 5개뿐(`KeyDerivationTests.swift`). DatabaseReader/automation/sync/device-info/SHA-512 recovery 테스트 **없음**.
- 권한: **Full Disk Access**(모든 명령) + **Accessibility**(send/harvest/inspect)를 터미널에 부여 필요.

### 2.5 위험·유지보수·이슈
- 안전 규칙(AGENTS.md:238-244, SKILL.md): 타인에게 테스트 전송 금지(--me/--dry-run), 전송 간 ≥2초, 23:00–07:00 회피, 전송 전 확인 — **전부 조언 텍스트, 코드 미강제**(레이트리밋/시간대 로직 없음). 명시적 ToS/밴 경고는 약함.
- GitHub 이슈(전 7개) 파손 주제: **userId 자동검출**이 지배적(#2 FSChatWindowTransparency 키 소멸, #4 SHA-512 10초 타임아웃이 userId>~22M에서 실패, #14/#16 후보/브루트포스 범위 초과), 설치경로 하드코딩(#22 `카카오톡.app` 미인식), 전송 행(#9 send hang, --dry-run은 정상). 최종 커밋 2026-03 이후 정체.

### 2.6 채택할 아이디어 / 피할 함정
- 채택: ① `KakaoCore` 라이브러리 / 얇은 ArgumentParser 프런트 분리, 모든 읽기에 `--db`/`--key` 탈출구. ② cipher-compat [3,4] 프로브 루프 + 저렴한 sqlite_master 검증(키 정합성 체크 패턴). ③ 다단계 비밀 발견 + 수동 오버라이드로 우아한 degradation. ④ `security` CLI로 Keychain ACL 회피. ⑤ NDJSON + `--since-log-id` high-water 재개.
- 함정: ① SHA-512 pre-image 브루트포스는 근본적으로 확장 불가(단일스레드, 매직 타임아웃). ② 설치경로 하드코딩(bundleId/NSWorkspace로 해소할 것). ③ Keychain 항목 ACL 부재 + argv 비밀번호 노출. ④ webhook 무서명·http 허용. ⑤ **로컬 DB가 채팅당 수개 메시지만** 보유 → 읽기/검색 범위가 harvest 없이는 매우 제한적이고, harvest는 UI 구동이라 느리고 깨지기 쉬움. ⑥ MetadataStore write-only 데드코드. ⑦ 미선언 런타임 의존(peekaboo/cliclick). ⑧ UI 자동화의 타이밍 취약성(고정 sleep 다수, send hang #9).

## 3. channprj/kmsg (Swift, macOS)

### 3.1 기본 정보
- 언어/런타임: Swift tools 6.0, macOS 13+(`Package.swift:1,9`). 버전 `MAJOR.YYMMDD.PATCH`(VERSION 1.260921.0). 최종 커밋 2026-09-21(`54cbff7`). Stars 276 / forks 47 / open issues 3. 라이선스 MIT(© Park Hee Chan).
- 의존성(관찰): 런타임 SPM은 `swift-argument-parser` 1.7.0 단 하나(`Package.resolved:5-10`). 내부 빌드 플러그인 VersionGenPlugin. 프레임워크: ApplicationServices(AXUIElement), AppKit(NSWorkspace/NSPasteboard), CoreGraphics(CGEvent), CryptoKit. `tools/kmsg-mcp.py`는 **레거시/참고용**(표준 라이브러리만), 실제 MCP 진입점은 네이티브 `kmsg mcp-server`.
- 배포: Homebrew `channprj/tap/kmsg`(최근 10개 버전 `kmsg@X` formula 유지), 직접 다운로드 universal 바이너리, 소스 빌드. codesign/notarization 단계는 관찰 안 됨.

### 3.2 통합 방식 — 순수 Accessibility 자동화 (DB/네트워크 전혀 없음)
**LOCO·REST·SQLite·소켓 전무**(관찰). Sources 내 유일한 URL은 Homebrew 설치 스크립트. 저자가 밴/ToS 위험 때문에 LOCO를 의도적으로 피했다고 명시(`ARCHITECTURE.md:203-210,276-280`). 세 프로젝트 중 **가장 순수한 UI 자동화**.

- 앱/창 찾기(관찰): 번들 ID `com.kakao.KakaoTalkMac`를 `NSRunningApplication`으로. 채팅 리스트 창은 제목에 "채팅" 포함 창 → "카카오톡" → `chatrooms` id 요소 포함 창 순(KakaoTalk 26.x 기준 주석). 모든 AX 호출에 메시징 타임아웃(`KMSG_AX_TIMEOUT` 기본 0.25s). 트리 탐색은 BFS + `maxNodes` 예산.
- 채팅 열기(`ChatWindowResolver.swift`): ① 제목 퍼지매칭(exact/prefix/contains/역contains + 선생님/님/씨 경칭 제거)으로 기존 창 재사용 → ② `--chat-id`면 리스트 행 스캔→ID 매핑→AXPress/AXConfirm 또는 AXSelected+Enter → ③ 검색 필드에 AXValue 설정(안 되면 CGEvent 타이핑)→결과 2-pass 폴링→**CGEvent 실제 더블클릭**(스캔 중 캡처한 좌표, 커서 저장·복원)으로 활성화. 결과 행이 AXPress/Enter 무시하고 수백 ms 내 핸들 stale되는 KakaoTalk 특성 대응.
- 읽기: 입력창은 role별 가중치 스코어링(AXTextArea 12000 등 + y위치/높이/포커스), transcript root는 공간 스코어링. 행 파싱(`TranscriptReader.swift`): body=최장 AXTextArea, author/time=AXStaticText 토큰, **date=시간 라벨의 AXHelp 툴팁**, 좌우=수평 위치(≤0.56 좌, ≥0.62 우) 또는 아바타 위치. **스크롤 없음** — AX 트리에 이미 있는 행만 반환(off-screen 행은 음수 y로 트리에 존재, issue #3).
- 전송(`SendCommand.swift`): activate+AXRaise → 입력창 포커스 → AXValue 설정(안 되면 CGEvent 유니코드 타이핑 10ms 간격, `.cghidEventTap`) → **CGEvent Return(keycode 36)**. "성공"=입력창 값 변경/비워짐. 입력창 못 찾으면 **강제 타이핑 폴백**(포커스된 아무 데나 입력 후 Enter, 확인 없이 true 반환).
- 이미지 전송(`SendImageCommand.swift`): `NSPasteboard.general` 덮어쓰고 **복원 안 함** → Cmd+V → "전송"/"Send" 시트 버튼. 시트 없어도 성공 출력.
- **background-safe read**: 이미 노출된/포커스된 창만 수용, activate/resize/close 안 함, 아니면 `BACKGROUND_SAFE_BLOCKED`.
- **잠금화면 해제**(`KakaoTalkAuthenticator.swift:623-802`): 얕은 탐지(상위 2레벨, "잠금 모드" 텍스트 + AXScrollArea/Table 없음 + 입력 필드 정확히 1개, 제목 무시). 패스코드 순서: 저장된 잠금 패스코드 → 계정 비밀번호 → TTY. **정확히 1회 시도**(반복 실패 시 KakaoTalk 로그아웃).
- **AX 경로 캐시**(`AXPathCache.swift`): `~/.kmsg/ax-cache.json`, v2, 7일 TTL. 슬롯(searchField/messageInput/transcriptRoot 등). 경로=(childIndex,role,id,title) 단계 리스트, index→id→role+title 순 해석. 루트 fingerprint(role|id|40pt 버킷 크기)로 키잉. **KakaoTalk 버전(`CFBundleShortVersionString+CFBundleVersion`) 변경 시 전체 무효화**. 매 히트마다 predicate 재검증.

### 3.3 인증·권한
- 자격(관찰): KakaoTalk 계정 ID/비밀번호를 `~/.config/kmsg/credentials.json`에 저장. 비밀번호·잠금 패스코드는 AES-GCM 암호화하나 **256비트 키가 같은 디렉터리 `credentials/primary.key`에 평문으로 공존**(0700/0600). Keychain 미사용(ARCHITECTURE.md:156-158 명시).
- 자동 로그인: 로그인 폼 채우기(AXValue, 안 되면 타이핑), QR 화면 "다시 시작", "이미 로그인" 대화상자 닫기. 폼 못 찾으면 **블라인드 키보드 로그인**(Cmd+A/타이핑/Tab 시퀀스) — activate 실패 시 전면 앱에 비밀번호 입력 위험. 비-background 명령마다 `AuthBootstrap`이 자동 트리거.
- macOS 권한: **Accessibility만**(`AXIsProcessTrusted`). Screen Recording/Input Monitoring/Automation 불요. CGEvent 포스팅이 AX 신뢰로 커버된다는 건 추론.

### 3.4 CLI 표면·MCP·설정
- 명령(`kmsg.swift:41-54`, 기본 `status`): status, auth login, chats, read, watch, send, send-image, inspect, cache(status/clear/export/import/warmup), mcp-server, update. 공통 플래그 `--trace-ax`, `-k/--keep-window`, `--deep-recovery`, `--json`. `send --dry-run`은 KakaoTalk 접촉 전 종료. `send-image`는 dry-run·chat_id 없음.
- JSON: `read`={chat,fetched_at,count,messages:[{author,time_raw?,date?,body,has_image,...}]}. `author`는 미해결 시 `"(me)"`(우측 행 + 앵커 없는 좌측 행 포함 → 엄밀히 "내가 보냄" 아님). `chat_id`=정규화 제목 SHA-256 앞 6바이트 hex(`chat_` 접두, 충돌 시 `_2`...), **로컬 전용**(`~/.kmsg/chat-registry.json`).
- watch: AXObserver 없는 **순수 폴링**(`--poll-interval` 기본 0.2s, 0.2–10 clamp). 시작 시 fingerprint 안정화, 매 틱 최대 120개 읽어 **최장 정렬 overlap diff**로 신규 검출(body 일치 + 타임스탬프 60s 이내 + author 일치). watch 시작 이후 타임스탬프만 emit. 출력은 **이벤트당 여러 줄 pretty-print(NDJSON 아님)** — 문서(`docs/openclaw.md:92`)의 "한 줄 한 객체"와 불일치.
- MCP 서버(`MCPServerCommand.swift`): stdio, **Content-Length 프레이밍 vs NDJSON 자동 감지**(issue #13 수정). 프로토콜 `2024-11-05` 하드코딩, 서버명 `openclaw-kmsg-mcp`. 요청마다 **kmsg 바이너리를 서브프로세스로 재실행**(타임아웃 read 8/15s, send 10/18s). 툴: `kmsg_read`, `kmsg_send`(**채팅 이름만**), `kmsg_send_image`. chats/watch 툴 없음. `confirm` 기본 false → **즉시 전송**, true면 `CONFIRMATION_REQUIRED` 반환.
- 상태/설정: `~/.config/kmsg/credentials{.json,/primary.key}`, `~/.kmsg/ax-cache.json`, `~/.kmsg/chat-registry.json`. env 다수(`KMSG_AX_TIMEOUT` 등).
- 자동 업데이트: PATH/고정 경로에서 brew 탐색, 없으면 **remote install.sh를 curl→bash 실행**, 그 후 tap install/upgrade, 직접 설치 바이너리를 심볼릭 링크로 교체(필요 시 sudo).

### 3.5 아키텍처·테스트·CI
- 레이어: Commands → AuthBootstrap → KakaoTalk 도메인 → Accessibility 헬퍼 → AXUIElement/CGEvent/AppKit. 머신 파싱 가능한 오류 코드(`FOCUS_FAIL`, `INPUT_NOT_REFLECTED`, `SEARCH_MISS`, `BACKGROUND_SAFE_BLOCKED` 등), 진단은 stderr·JSON은 stdout.
- 테스트(`tests/*.py`, unittest): 대부분 **소스 텍스트 contract 테스트**(Swift 파일의 부분문자열/순서 단언, 동작 아님). 행동 테스트는 update/sync_homebrew_tap/version_gen/release뿐. **AX 파싱 로직 테스트 없음.** CI(macos-14)는 3개 모듈만 실행. `AGENTS.md:16`은 "테스트 없음"으로 stale.

### 3.6 한계·위험·주목할 결함
- 위험 명시: 비공식, ToS/법적 책임은 사용자, 계정 제한/데이터 손실 가능. LOCO로 밴 사례 있어 AX가 "상대적으로 안전"하다는 저자 판단.
- 버전 호환 매트릭스 없음(코드 주석 "KakaoTalk 26.x" + 캐시 fingerprint뿐, issue #7). 한/영 UI 문자열 하드코딩 다수 → 릴리스마다 취약(issue #3, #5).
- **레이트리밋/쿨다운/중복전송 방지 코드 전무** — 문서 권고(draft-then-approve)와 skill 지침만. send-image는 dry-run 없음.
- 관찰된 결함(서브에이전트 분석): ① MCP `extractErrorCode`가 `"not found"`를 `SEARCH_MISS`보다 먼저 검사 → 검색 실패가 "바이너리 없음"으로 오보고, CHAT_NOT_FOUND deep-recovery 재시도 미발화. ② send/send-image가 **이미 열려있던 창도 닫음**(openedTransiently 미확인) → watch+send 동시 사용 깨짐. ③ 오타겟 가능(퍼지매칭 "Kim"→"Kim Team", MCP send에 chat_id 없음 issue #10; 강제 타이핑; 블라인드 로그인 비밀번호 오입력). ④ 전송 성공 판정이 약함(입력창 변경만, transcript readback 없음) → MCP 타임아웃 중 종료 시 재시도로 **중복 전송** 가능. ⑤ watch 갭(분 단위 타임스탬프로 첫 메시지 유실, 타임스탬프 없는 행 drop, 스크롤백 없음, 같은 분 동일 텍스트 collapse). ⑥ `read`가 일부 실패를 exit 0 + 평문으로 → `--json`/MCP가 INVALID_JSON.

### 3.7 채택할 아이디어 / 피할 함정
- 채택: ① **자가치유 AX 경로 캐시**(index/role/id/title 단계, 매 히트 검증, 앱버전 fingerprint, TTL) — AX 자동화 성능·안정성의 핵심. ② 노드 예산 BFS + 2단계 스코어러(싼 공간 스코어 먼저, top-3만 BFS). ③ **스캔 중 클릭 좌표 미리 캡처**(핸들 stale 전) + 커서 복원. ④ AXHelp 툴팁에서 날짜 추출. ⑤ 전 레이어 관통하는 명시적 `backgroundSafe` 모드. ⑥ **안정적 오류 코드**를 stderr/stdout에 → MCP가 힌트로 매핑. ⑦ CLI를 서브프로세스로 재사용하는 dual-framing MCP stdio 서버(로직 단일화). ⑧ 이름 해시 기반 합성 로컬 chat_id.
- 함정: ① UI 문자열·레이아웃 휴리스틱 하드코딩 → 릴리스마다 파손. ② 전송 성공 판정·중복 방지 미흡. ③ 창 닫기 부작용. ④ 비밀번호 키가 같은 디스크 공존 + 자동 업데이트의 remote bash + sudo. ⑤ contract 테스트가 동작 아닌 소스 텍스트 고정 → 리팩터링에 취약, 실제 AX 파싱 회귀 미검출.

- 로컬 SQLCipher DB 직접 복호화는 openkakao-cli·kakaocli **둘 다 KakaoTalk 26.5.0+에서 봉인**됨(파일명·키를 새 템플릿으로 마이그레이션, 키가 NTSetting에 AES 저장). 공개 gist 공식은 이제 동작 안 함. 지속 가능한 1차 경로가 아니다.

- 수신 감지에서 openkakao-cli의 **알림센터 DB(usernoted) 폴링**이 창 무관·자기발신 배제·밴표면 0으로 가장 우수하나, 음소거/포커스 채팅은 못 본다.

## 5. 권장 설계 방향

### 5.1 접근 방식 선택 (트레이드오프)
| 접근 | 장점 | 단점 | 판정 |
|---|---|---|---|
| LOCO 재구현 | 서버 직접, 창 불요, 완전한 히스토리/송수신 | **밴/계정삭제 실증**, 최신 빌드 잦은 파손, 유지보수 폭탄, 인증서/핸드셰이크 추적 | 1차 경로로 **비권장**(연구/옵트인 한정) |
| 로컬 DB 읽기 | 서버 접촉 0, 빠름, 구조화 데이터 | **26.5.0+ 봉인**(키 AES 저장+마이그레이션), 동적 훅은 재서명→로그아웃으로 NO-GO | 현재 **불가**, 향후 벤더가 완화하면 재검토 |
| UI 자동화(AX) | 서버 접촉 0(밴표면 최소), 공식 앱 조작이라 상대적 안전, 세 선례 검증 | UI 변경 취약, 창 가시성/포커스, 느림, 전송 확정 어려움 | **1차 권장 경로** |
| 알림센터 DB(usernoted) | 창 무관, 자기발신 배제, 밴표면 0, 평문 SQLite | 음소거/포커스 채팅 누락, 지워진 알림 replay 불가, 수신 전용 | **수신 감지 1차 권장** |

**권장 조합**: 전송·단발 읽기는 **AX 자동화**, 수신 스트림은 **알림센터 DB 폴링(+AX 보완)**. 로컬 DB/LOCO는 명시적 opt-in 연구 플래그 뒤로 격리.

### 5.2 언어 선택
- 세 선례: Swift 2 / Rust 1. **Swift**는 AX/AppKit/CoreGraphics 네이티브 바인딩이 1급이라 자동화 코드가 짧고(kmsg·kakaocli 증명) macOS 권한 모델과 잘 맞는다. **Rust**(openkakao-cli)는 안전성·크로스플랫폼 잠재력·프로토콜 파싱에 강하나 AX는 서드파티 크레이트(`accessibility`) 의존이고 macOS 전용 cfg 분기가 늘어난다.
- 판정: **macOS 전용·AX 중심이면 Swift 권장.** 단 프로토콜(LOCO/BSON) 재구현 비중을 크게 둘 계획이면 Rust도 합리적. 신규 CLI의 1차 경로가 AX이므로 Swift를 기본 추천하되, 조직의 기존 Rust 역량이 크면 Rust+accessibility도 수용 가능.

### 5.3 플랫폼 범위
- 세 선례 전부 macOS 전용. Windows 클라이언트는 Themida 보호로 정적 분석이 사실상 불가(동 저장소 artifact-collection 노트). **1차 범위는 macOS로 한정**하고, Windows/Android는 LOCO 경로를 선택할 때만 별도 과제로.

### 5.4 반드시 채택할 설계 요소
1. **에이전트 안전은 코드로 강제**(openkakao-cli safe-send 모범): 제안/승인 분리, 로컬 outbox, OS 기기소유자 인증(LAContext), 레이트리밋(채팅당/전역/시간대), 전송 결과 verified/not_sent/uncertain 3분류 + uncertain 자동 재시도 금지. 세 선례 중 kakaocli·kmsg는 조언 텍스트만이라 위험.
2. **전송 확정은 transcript readback으로**(kmsg의 "입력창 변경" 판정 약점 회피): 발신 후 동일 텍스트 outgoing 버블 재확인. 중복 전송 방지(idempotency key).
3. **자가치유 AX 경로 캐시 + 앱버전 fingerprint 무효화**(kmsg): AX 성능·안정성 핵심. 노드 예산 BFS, 2단계 스코어링, 스캔 중 좌표 캡처 + 커서 복원.
4. **수신은 알림센터 DB**(openkakao-cli notif-watch): `~/Library/Group Containers/group.com.apple.usernoted/db2/db` read-only 폴링, `방ID_메시지ID` idempotency, durable outbox + at-least-once. AX watch는 포커스/음소거 채팅 보완재.
5. **일관된 머신 파싱 오류 코드**(kmsg) + 모든 실패를 non-zero exit + 구조화 JSON으로(kmsg의 exit-0 평문 버그 회피). `--json`/NDJSON 일급.
6. **MCP 서버**(kmsg): dual-framing stdio, CLI 로직 단일화. 단 `confirm` 기본값을 **전송 안 함**으로(kmsg는 즉시 전송 — 위험), chat_id 지원(이름만 금지, 오타겟 방지).
7. **자격 보안**: Keychain + per-app ACL(kakaocli의 ACL 부재, kmsg의 키 공존 둘 다 회피). 비밀번호를 argv로 받지 말 것. 파일 경로는 0600.
8. **설치경로는 bundleId/NSWorkspace로 해석**(kakaocli·kmsg의 `/Applications/KakaoTalk.app` 하드코딩 → `카카오톡.app` 미인식 버그 회피).
9. **버전 호환 정책**: 지원 KakaoTalk 버전 매트릭스 명시 + UI 변경 시 graceful 실패/경고. 한/영 UI 문자열 외부화.
10. **테스트**: AX 파싱·프로토콜 빌더의 **동작** 테스트(kmsg의 소스텍스트 contract 한계 회피, openkakao-cli의 프로토콜 단위 테스트 본받기).

### 5.5 피할 함정 요약
- LOCO write를 기본 활성화하지 말 것(계정 삭제 실증). 미등록 기기 로그인 반복 금지(차단 트리거).
- 로컬 DB 복호화를 1차 의존으로 삼지 말 것(26.5.0+ 봉인).
- 전송 성공을 약하게 판정하거나 클립보드를 복원 없이 덮어쓰지 말 것(kmsg send-image).
- 이미 열린 창을 닫는 부작용, 강제 타이핑/블라인드 로그인의 오타겟·비밀번호 오입력 경로 제거.
- 레이트리밋·쿨다운을 문서가 아닌 코드로.
- watch의 분 단위 타임스탬프 유실·스크롤백 부재를 알림센터 DB 경로로 보완.
