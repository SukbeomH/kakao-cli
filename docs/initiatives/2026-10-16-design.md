# kakao-cli 설계 (v0)

작성 2026-10-16. 선행조사(`2026-10-16-prior-art.md`)·수집원장(`2026-10-16-artifact-collection.md`)의 결정을 코드 설계로 옮긴 문서.

## 1. 한 줄 요약

Proxmox 위 전용 VM에서 **redroid(Docker)로 공식 Android 카카오톡을 구동**하고, **adb + UIAutomator**로 조작하는 Linux CLI. 서버 프로토콜(LOCO) 재구현도, 로컬 DB 복호화도 하지 않는다.

## 2. 왜 이 경로인가 (요약)

- LOCO 직접접속 = 계정차단 실증 → 비채택. 로컬 DB = 26.5.0+ 봉인 + Linux엔 읽을 DB 없음 → 비채택.
- UI 자동화가 밴 표면이 가장 작고(공식 앱 조작) 세 선행사례가 공히 수렴한 경로.
- Linux 런타임이므로 macOS AX·알림센터는 불가. Windows/Wine은 Themida anti-Wine 위험 + 스킨 커스텀 드로잉으로 UIA 트리 부재 → 좌표/OCR만 가능해 취약.
- Android는 **리소스 ID가 난독화되지 않아**(아래 §5) UIAutomator로 견고하게 타겟팅 가능. 디컴파일한 APK가 그대로 자동화 계약서가 된다.

## 3. 런타임 토폴로지

```
[개발/제어 호스트]  --- adb over TCP (5555) --->  [Proxmox VM/CT]
   kakao-cli (Python)                               Waydroid (Android 컨테이너)
                                                      └ com.kakao.talk (ARM, libndk 변환)
```

- VM/CT 요건: binder(커널 모듈 또는 호스트 전달), Waydroid, **ARM 변환 레이어(libndk_translation/libhoudini)** — 카카오톡이 ARM 전용 so만 포함하기 때문. GApps(Play 로그인용).
- CLI는 adb 클라이언트로만 접속 → 헤드리스·원격·다중 디바이스 가능. GUI 디스플레이 불필요(Waydroid 쪽에서 렌더).
- 이 샌드박스(비특권 LXC)에서는 Waydroid 구동 불가 → 여기선 코드 작성·디컴파일 참조·단위테스트만, 실구동 검증은 VM/CT에서.

### 3.1 기기 정체성 — 태블릿 공존 로그인 (중요)

기존 **폰과 동시 사용**하려면 Waydroid가 카카오톡에 **태블릿(서브 기기)**으로 인식돼야 한다. 그렇지 않으면 같은 계정 두 번째 "폰"으로 취급돼 **기존 폰이 로그아웃**된다.

- 카카오톡의 태블릿 공존 로그인("다른 기기와 함께 사용" 옵션)은 **특정 갤럭시탭 모델 allowlist로 서버가 게이트**한다(샤오미·레노버 등 비허용 기기는 옵션 미표시 → 폰 로그아웃). 실기기에선 루팅으로 모델 스푸핑하는 사례.
- 디컴파일 근거(26.8.3 dex): `sub_device`/`subDevice`/`SUB_DEVICE`, `isTablet`/`is_tablet`, `deviceType`/`device_type`, `useSub`, `companion` 심볼 존재. 갤럭시탭 모델 문자열 `SM-T230`/`SM-T580`/`SM-X900` 존재. 단 "다른 기기와 함께" 정확 문구는 코드에 없음 → **최종 허용은 서버가 기기 지문으로 판정**하는 것으로 추정.
- **Waydroid는 컨테이너라 build.prop 스푸핑이 깔끔**(실기기 루팅 불필요): `waydroid prop set`/resetprop로 `ro.product.manufacturer=samsung`, `ro.product.model`/`ro.product.device`를 **허용 갤럭시탭(예: 최신 SM-X 계열)**으로, `ro.build.characteristics=tablet`, 매칭 `ro.build.fingerprint`, 디스플레이를 **sw600dp+ 태블릿 해상도/밀도**(예: 1600×2560 + 적정 dpi)로 설정.
- **검증 규약**: VM/CT 로그인 화면에서 "다른 기기와 함께 사용" 옵션이 뜨는지 실측으로 확정. 안 뜨면 폰 로그인 금지(데이터 손실 위험) → 다른 모델 지문으로 재시도. allowlist는 시기별로 바뀌므로 코드에 하드코딩하지 말고 **설정 가능한 기기 프로필**로 둔다.
- 로그인 시 폰에 서브기기 등록 승인 알림이 뜰 수 있음(기기 등록 플로우). 이 1회 플로우는 수동 또는 UI 자동화로 처리.

## 4. 아키텍처 (레이어)

1. **transport**: adb 연결 관리(`adb connect host:5555`), 디바이스 선택, 셸 실행, 파일 push/pull, 재연결/타임아웃. `adbutils` 래핑.
2. **app**: 앱 생명주기(기동/포그라운드 확인/현재 액티비티 조회 `dumpsys activity`), 딥링크·intent 발사(`am start`), 패키지 버전 fingerprint.
3. **ui**: UIAutomator 엔진 — `uiautomator dump` XML 파싱, 노드 탐색(resource-id/text/content-desc/class), 탭/입력/스와이프, **노드 경로 캐시 + 앱버전 fingerprint 무효화**(kmsg 교훈). 셀렉터는 §5 계약 사용.
4. **actions**: 고수준 동작 — `send_text`, `open_chat`, `read_room`, `list_rooms`. 각 동작은 멱등키와 전송확정 규약을 가짐.
5. **receive**: 수신 스트림 — Android 알림 조회(`dumpsys notification` 또는 NotificationListener 동반 앱)로 신규 메시지 감지, durable at-least-once 아웃박스, dedup(roomId+msgId).
6. **safety**: 제안/승인 분리, 레이트리밋(채팅당/전역/시간대), 블라인드 전송 금지, 전송결과 3분류(verified/not_sent/uncertain, uncertain은 자동재시도 금지).
7. **session**: 자격·세션(최초 Play/카카오 로그인은 UI 자동화 또는 수동 1회), 설정 `~/.config/kakao-cli/`(0600), 비밀번호를 argv로 받지 않음.
8. **io**: 일관된 종료코드 + 구조화 JSON/NDJSON. 모든 실패는 non-zero + 머신 파싱 오류코드.
9. **(선택) mcp**: stdio MCP 서버로 동일 로직 노출. `confirm` 기본값 = 전송 안 함. chat_id 필수(이름만으로 오타겟 금지).

## 5. 자동화 계약 (디컴파일 근거, 26.8.3)

> 리소스 ID는 `com.kakao.talk:id/<name>`. jadx가 붙인 `_res_0x…` 접미사는 split 중복 구분용이며 런타임 ID명이 아님.

- 패키지 `com.kakao.talk`, 런처 액티비티 `com.kakao.talk.activity.SplashActivity`.
- 채팅방 `com.kakao.talk.activity.chatroom.ChatRoomHolderActivity`.
- **나에게 보내기(안전 테스트 대상)** `com.kakao.talk.activity.MemoChatConnectActivity`.
- 채팅목록 화면 ID: `chatroom_list`, `chats`, `chats_layout`.
- 채팅방 ID: 입력창 `compose_view`/`compose_content`/`editTextRootLayout`, 전송 `sendButton`, 말풍선 텍스트 `message`, `tv_message`.
- intent 전송 경로(UI 탭 대안): exported `RecentExcludeIntentFilterActivity`가 `ACTION_SEND`/`SENDTO`/`SEND_MULTIPLE`(mime text/image/video/audio/*) 처리 → 공유 시트로 특정 방 전송.
- 입장 딥링크: `SplashConnectActivity`의 VIEW + `ENTER_CHAT_ROOM`, 스킴 `kakaotalk`/`kakaolink`/`kakaoopen`.

검증 규약: 셀렉터·intent는 **라이브 VM/CT에서 `uiautomator dump`로 실측 확정** 후 코드에 고정(정적 ID는 후보, 런타임이 진실).

## 6. 명령 표면 (초안)

```
kakao doctor                      # adb·디바이스·앱버전·권한 점검
kakao rooms list [--json]         # 채팅방 목록
kakao send <room> <text> [--yes]  # 전송(기본은 제안→승인; --yes로 즉시)
kakao read <room> [--limit N]     # 최근 메시지 읽기
kakao watch [--durable] [--json]  # 수신 스트림(NDJSON)
kakao memo <text>                 # 나에게 보내기(안전 테스트)
```

## 7. 언어 결정

- 경로가 adb 오케스트레이션(+XML/JSON 파싱)이라 프로토콜/암호 재구현 비중이 사라짐 → Rust/Swift의 이점이 무의미.
- **Python 3.11 + uv**: `adbutils`/`uiautomator2` 등 Android 자동화 생태계가 가장 성숙, 반복 개발 빠름, VM/CT에 `uv` 설치 간단.
- 대안: 단일 바이너리 배포가 요건이면 Go.

## 8. 반드시 지킬 설계 요소 (선행 교훈)

safe-send(제안/승인+OS인증+레이트리밋 코드강제), transcript readback 전송확정+idempotency, 자가치유 AX 경로 캐시+앱버전 fingerprint, 알림 기반 수신 durable at-least-once, 일관 오류코드+JSON, MCP는 confirm 기본 전송금지·chat_id 필수, 자격은 Keychain 대체로 파일 0600+최소노출.

## 8.5 로그인 자동화 (사용자 요청)

목표: `kakao login`이 로그인 UI를 최대한 자동으로 몰고 간다. 단 **구조상 사람(폰)이 해야만 하는 두 지점**이 있어 완전 무인은 불가 — 이를 명확히 분리한다.

자동화 가능(CLI가 UIAutomator로 수행):
- 앱 기동 → 로그인 방식 선택 → **카카오계정 이메일+비밀번호 입력**(필드에 set + 다음).
- "다른 기기와 함께 사용(태블릿/서브기기)" 옵션 선택.
- 각 단계 화면 전이 확인·재시도, 실패 시 구조화 오류.

사람이 필요(폰에서 발생):
- **SMS 인증번호(OTP)**: 사용자 폰으로 전송됨 → CLI가 받을 수 없음. 설계: `kakao login --otp <code>` 또는 대화형 프롬프트로 **사용자가 코드를 넣으면 CLI가 입력**. (옵션: 안드로이드 SMS 수신을 다른 경로로 자동 캡처하는 것은 범위 밖/위험.)
- **폰 측 서브기기 등록 승인 탭**: 기존 폰에 뜨는 승인은 그 폰에서 눌러야 함. CLI는 승인 대기 상태를 감지·안내만.

흐름(설계): `kakao login --email <id> [--password-stdin] [--device-profile galaxy-tab-s9]`
→ UI 몰기 → OTP 프롬프트(사용자 입력) → 폰 승인 대기 감지 → 로그인 완료 확인(채팅목록 화면 도달)으로 성공 판정. 자격은 argv 금지(stdin/프롬프트), 세션 상태는 앱이 보유(토큰을 우리가 저장하지 않음).

## 8.6 기기 프로필 결정 (사용자 위임)

태블릿 모델은 에이전트가 결정: 기본 **Galaxy Tab S9 (SM-X710, Wi-Fi, gts9wifi)**. 최신 S 시리즈로 KakaoTalk 태블릿 공존 allowlist 가능성이 높고 펌웨어 지문 확보가 쉽다. 구체 `ro.build.fingerprint`는 지문 조사(`2026-10-16-tablet-fingerprint.md`) 확정값으로 교체. 로그인 화면에서 "다른 기기와 함께 사용"이 안 뜨면 프로필 교체(설정 가능, 하드코딩 금지).

## 9. 미해결·위험

- Waydroid x86_64에서 ARM 변환 레이어 안정성(카카오톡 기동 여부)은 VM/CT 실측 필요.
- Play 로그인/기기 등록을 자동화할지 수동 1회로 둘지.
- 앱 업데이트 시 리소스 ID/레이아웃 변경 → fingerprint 무효화 + graceful 실패.
- 과도한 자동화가 이상탐지로 이어질 가능성(레이트리밋·인간 유사 지연으로 완화).
