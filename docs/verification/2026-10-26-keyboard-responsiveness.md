# 키보드 입력 반응성 개선 검증

검증일: 2026-10-26. `kakao` VM을 먼저 종료했다. 실제 입력 검사는 개인정보나
KakaoTalk 대화방을 사용하지 않고 독립 `android-console` VM의 Android 설정 검색창에서
진행했다. 검증 후 독립 VM도 종료했다.

이 기록은 확정된 글자의 전송 지연 개선에 대한 것이다. 이후 조합 중 마지막 음절 표시 문제도
[실시간 한글 조합 전달](2026-10-26-korean-preedit.md)로 수정했다.

## 변경

- 조합이 끝난 글자의 기존 60ms 배치 타이머를 제거해 첫 요청을 즉시 보낸다.
- 입력 요청은 하나씩 완료를 확인한다. 전송 중 쌓인 인접 텍스트만 합쳐 느린 연결의
  대기 요청을 줄인다. Enter·Backspace·붙여넣기 경계를 넘어 합치지 않는다.
- 한글 IME의 조합 중 글자는 보내지 않는다. 일반 입력에는 ADBKeyBoard를 계속 사용해
  클립보드 내용을 바꾸지 않는다.
- 실패한 요청은 적용 여부가 불확실하므로 재전송하지 않는다. 대기 글자와 Enter도
  취소하고 기기 내용을 확인하라는 상태를 표시한다. 사용자의 다음 입력부터 다시 처리한다.
- PNG 캡처는 별도 읽기 스레드에서 실행한다. 캡처가 멈추어도 직렬 입력 Worker가
  텍스트와 키의 완료 응답을 처리할 수 있다.
- 검사 중 발견한 런타임 내보내기의 임시 Python 바이트코드 포함 문제도 수정했다.

공통 `android_console.webui`와 Worker의 변경으로 Kakao 웹 콘솔에도 같은 코드가 적용된다.
독립 웹 콘솔 이미지를 재빌드해 실측했다. 종료된 `kakao` VM의 기존 컨테이너 이미지는
이번 검사에서 재빌드하지 않았다. 다음 Kakao 실행 시 `limactl start kakao` 후
`./scripts/lima-compose.sh up -d --build`로 반영한다.
CLI/TUI의 메시지 전송 방식을 바꾸는 변경은 아니다.

## 실제 Android 전후 비교

Apple Silicon 호스트, Lima 2 CPU / 4GiB / 20GiB, 동일한 Android 데이터와 입력기,
Chrome 475×988에서 측정했다. 브라우저 입력부터 해당 HTTP 응답을 받을 때까지의
지연이며 화면 표시까지의 시간은 아니다. 병합 요청의 각 글자는 같은 완료 시각을 사용한다.
렌더러별 각 시나리오를 전후 한 번씩 실행했으므로 장시간 통계나 원격 호스트 성능 보장은 아니다.

| 시나리오 | 입력 조건 | 중앙값 전→후 | P95 전→후 | 첫 요청 전→후 |
| --- | --- | --- | --- | --- |
| H.264/WebCodecs 한글 | 10글자, 150ms 간격 | 88→28ms | 111→43ms | 83→20ms |
| H.264/WebCodecs 빠른 영문 | 40글자, 20ms 간격 | 62→44ms | 98→67ms | 66→3ms |
| PNG 한글 | 8글자, 150ms 간격 | 86→26ms | 102→41ms | 81→12ms |

모든 시나리오에서 Android UI XML로 읽어낸 최종 문자열이 원문과 정확히 일치했다.
텍스트 요청 다음 Enter까지 완료됐으며 HTTP 입력 응답은 모두 200이었다.
빠른 영문 입력에서는 요청 수가 15→34개로 늘었다. 고정 대기를 없앤 결과로,
빠른 연결에서는 더 자주 보내고 느린 연결에서는 대기 중인 글자만 합친다.
검증 문자열은 설정 검색창에서 지웠고 개인 클립보드와 실제 휴대전화는 사용하지 않았다.

## 느린 연결 재현

실제 키보드 핸들러 코드를 Node VM에서 실행하고 HTTP 완료를 매 요청 120ms 지연시켰다.
이는 실제 네트워크 측정이 아닌 대기열 동작 검사다. 문자열 일치와 Enter 순서도 확인했다.

| 시나리오 | 첫 요청 전→후 | 입력 종료 후 Enter 완료 전→후 | 요청 수 전→후 |
| --- | --- | --- | --- |
| 10글자, 150ms 간격 | 61→3ms | 154→122ms | 11→11 |
| 40글자, 20ms 간격 | 63→1ms | 1033→224ms | 15→9 |

빠른 입력의 대기열 해소 시간이 약 78% 줄었다. 이는 120ms 완료 지연 조건의 결과다.

## 회귀 검사

- 전체 pytest: **229 passed**, 73.88초.
- 실제 입력 핸들러: 첫 요청 즉시 전송, 한 번에 하나의 요청, 대기 글자 병합,
  IME 조합 보류, Enter와 붙여넣기 순서, 실패 시 미전송 Enter 취소, 이후 입력 복구.
- PNG 캡처를 일부러 멈춘 상태에서도 텍스트·Enter의 완료 응답과 순서를 확인했다.
  사용하지 않는 화면에서는 캡처하지 않는 것도 확인했다.
- Kakao/Android 두 페이지 각각 Chrome fixture에서 클립보드 가져오기·넣기,
  일반 HTTP/권한 거부 대체 창, 우클릭 영역 제한을 통과했다.
